# Development

## Build and run

```sh
cargo run --release -p genha                 # desktop app
cargo run --release -p genha-cli -- --help   # headless CLI
cargo xtask ci                                    # everything a commit must pass
```

Linux needs the usual windowing libraries for the desktop app (`libxkbcommon`, X11 or Wayland, GTK 3 for
file dialogs). Fonts come from the system; with none installed the app falls back to the built-in
faces of the `epaint_default_fonts` crate (the CLI and tests then lay text out with approximate
metrics but draw nothing).

## Web

The same UI runs in the browser (`apps/genha-web`: eframe's web runner, WebGL2):

```sh
rustup target add wasm32-unknown-unknown
cargo xtask web                                   # builds dist/web (wasm + wasm-bindgen glue + index.html)
python3 -m http.server -d dist/web 8080           # any static server; open http://127.0.0.1:8080
```

`cargo xtask web` runs `cargo build -p genha-web --target wasm32-unknown-unknown --profile web` (the
`web` profile in `Cargo.toml`: `opt-level = "s"`, fat LTO, one codegen unit; it measured smaller
than `"z"`), then
`wasm-bindgen --target web` into `dist/web/` (it installs `wasm-bindgen-cli` with `cargo install
wasm-bindgen-cli --locked --version =<the wasm-bindgen version in Cargo.lock>` when missing; without
network, install that by hand), runs `wasm-opt -Oz` when Binaryen is installed, and copies
`apps/genha-web/index.html` (plain HTML and CSS) with the generated loader line in place of its
`<!-- genha:loader -->` marker. No handwritten JavaScript: the glue is generated by wasm-bindgen and
the browser calls (file picker, downloads) are Rust using web-sys (`crates/ui-egui/src/web.rs`).

In the browser:
- **Open…**, **Upload picture…** and the quick actions use the browser's file picker; files can
  also be dropped on the page. Bytes arrive a frame later and go to the engine
  (`cmd::file::open_bytes`, `image.place` with `data`, `cmd::content::quick_image_bytes`).
- **Save** downloads the `.genha` file (`cmd::file::design_bytes`); **Download** makes PNG, JPEG,
  SVG or PDF in memory (`cmd::export::page_bytes` / `pdf_bytes`) and the browser downloads it.
- **Fonts**: text starts in egui's built-in faces (Ubuntu Light, Hack, Noto Emoji from the
  `epaint_default_fonts` crate; `genha_ui_egui::fonts`). **Add fonts…** (or dropping `.ttf` /
  `.otf` / `.ttc` files) adds fonts with `font.add`, kept in IndexedDB; **Use installed fonts**
  loads the computer's fonts through the Local Font Access API (Chromium, after a permission
  prompt). Families without a bold or italic face get synthetic ones (`genha_render::synthetic`).
- **Storage**: Data Recovery copies, recent designs and added fonts go through the engine's
  `store::Store` trait: a folder on the desktop (`DirStore`), IndexedDB in the browser
  (`web::IdbStore`, loaded before the app starts, written back in the background). Recovery copies
  are written every 15 s in the browser; a reload offers them on the home screen.
- **Clipboard**: Ctrl+V of a picture places it (the page's paste event); Edit › Paste Picture
  reads the Clipboard API.
- Not in the browser (yet): the control channel.

Check the browser code with `cargo clippy -p genha-ui-egui -p genha-web --target
wasm32-unknown-unknown -- -D warnings` (`cargo xtask wasm`, part of `cargo xtask ci`, does this).
Hosting notes: [`packaging/web/README.md`](../packaging/web/README.md).

## Quality gates

`cargo xtask ci` runs: `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`
(including the no-panic lints), `cargo test --workspace`, `cargo xtask layers`, `cargo xtask assets`,
`cargo xtask cleanroom` and `cargo xtask wasm` (clippy for wasm32 on the engine and below, the UI and
the web app; needs `rustup target add wasm32-unknown-unknown`).

Video tests decode what the H.264 encoder wrote with `ffmpeg` when it is installed (CI installs it) and
require every sample to match the encoder's own reconstruction; without `ffmpeg` they are skipped.
`cargo test -p genha-video speed -- --ignored --nocapture` prints the encoder's speed.

## Robustness: GenHa never crashes

See [`AGENTS.md`](../AGENTS.md) › Never crash. In short: return `Result`, never index with numbers that
came from data, cap sizes, check floats, and fuzz every parser (`proptest`).

## Adding a feature

1. Model: if the document needs new data, add it to `crates/doc` with `#[serde(default)]` so older files
   still open (bump `genha_format::VERSION` only for breaking changes, and keep reading old ones).
2. Behaviour: a command in `crates/engine/src/cmd/<area>.rs` with a params doc and tests.
3. Rendering/export: `crates/render`, `crates/svg`, `crates/pdf`.
4. UI: a panel or button in `crates/ui-egui` that calls the command (`app.run(id, params)`).
5. Docs: the feature's row in [target-app-parity.md](target-app-parity.md), [gaps.md](gaps.md), the ROADMAP.
