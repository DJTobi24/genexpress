# Hosting GenHa on the web

`cargo xtask web` (see [docs/development.md › Web](../../docs/development.md#web)) writes a static
site to `dist/web/`:

| File | What it is |
|---|---|
| `index.html` | The page: plain HTML and CSS from `apps/genha-web/index.html` plus the generated loader line |
| `genha_web.js` | JavaScript glue generated by wasm-bindgen (ES module) |
| `genha_web_bg.wasm` | The app: about 9.6 MB without `wasm-opt` (measured 2026-10-13, `web` profile, after text shaping and the vector PDF exporter joined; before them 8.3 MB, 3.0 MB with gzip, 6.7 MB after `wasm-opt -Oz`) |

There is no server-side code and nothing leaves the user's browser: designs are opened from the
user's disk through the file picker and saved as downloads. Data Recovery copies, recent designs
(a copy and a thumbnail each) and fonts the user added are kept in the browser's IndexedDB
(database `genha`), per site: serving the app from another origin starts with empty storage. Upload the folder's contents to any
static host. All URLs are relative, so it works at a domain root or under a path.

## Server settings

- **MIME types:** `.wasm` as `application/wasm` (browsers refuse to stream-compile it otherwise),
  `.js` as `text/javascript`. Most servers, including `python3 -m http.server`, already do this.
- **Compression:** turn on gzip or Brotli for `.wasm`, `.js` and `.html`.
- **Caching:** the file names carry no content hash, so use `Cache-Control: no-cache` (revalidate)
  or a short `max-age` on all three files, or rename them per release.
- **No isolation headers needed:** GenHa doesn't use `SharedArrayBuffer`, so it needs no
  `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy`.

Local test: `python3 -m http.server -d dist/web 8080`, then open http://127.0.0.1:8080/.

## Browser requirements

WebAssembly and WebGL2: current Chrome, Edge, Firefox and Safari. Verified in Chromium
(headless, with the SwiftShader software renderer).

## Fonts

Until the user adds fonts, text is set in the built-in faces from the `epaint_default_fonts` crate
(Ubuntu Light under the Ubuntu Font Licence 1.0, Hack under MIT + Bitstream Vera, Noto Emoji under
OFL-1.1; see `NOTICE`), compiled into the `.wasm`; the repository holds no font files. Users can:

- add font files (`.ttf`, `.otf`, `.ttc`; not WOFF/WOFF2) with **Add fonts…** (home screen, Text
  panel) or by dropping them on the page; they are kept in IndexedDB for next time;
- in Chromium-based browsers, **Use installed fonts** (Local Font Access API,
  `window.queryLocalFonts`): the browser asks for permission once; afterwards they load at start.
  The page must be served from a secure context (HTTPS or `localhost`).

A family without a bold or italic face is drawn with synthetic bold (outlines thickened) and
italic (slanted), as on the desktop.
